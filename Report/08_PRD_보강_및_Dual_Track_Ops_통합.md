### 0.2 본 단계의 트리거

사용자가 첨부한 **"6.1 Dual-Track UI + Logic TDD"** 슬라이드 한 장과 함께,
*"Dual-Track UI + Logic TDD with MLOps 구조로 작업하고 싶다"* 는 의향을 제기.

→ 이 의향은 *그대로 수용*하면 두 가지 위험을 동반한다.
1. **MLOps의 부조화**: 4x4 마방진은 결정론적 도메인이며, ML 모델·학습 데이터·드리프트 개념이 *수학적으로 적용 불가능*. 형식만 빌리는 것은 §1 C-4("형식지로 환원") 원칙에 정면 위배.
2. **UI의 어휘 충돌**: 슬라이드의 "UI"는 화면(React 컴포넌트), 본 PRD §4.2 O-1은 UI 화면을 *명시적 배제*. 그대로 받으면 PRD 본문이 깨짐.

### 0.3 본 단계가 *해야 하는 것*

- 외부 프레임의 *정신*은 수용하되, *어휘는 본 PRD 내부에서 재정의*한다.
- "MLOps"는 *형식만 빌린* 상태로 박제하지 말고, *명시적 배제 대상*으로 외부화한다.
- 사용자가 진짜 원했을 가능성이 높은 *Ops 자동화*를 §13으로 신설하여 §1의 약속을 *기능적으로* 닫는다.
- §0/§6/§12의 Frozen 영역은 *건드리지 않는다*.

### 0.4 본 단계가 *하지 않는 것*

- 코드/테스트의 작성 — 본 단계는 PRD 단계이며, 구현은 후행.
- UI 화면(GUI/Web/CLI 디자인)의 도입 — §4.2 O-1을 *깨뜨리는* 변경은 거부.
- 진짜 ML 모델/MLOps 구성요소의 도입 — §13.5 OO-1로 명시적 배제.
- §0/§6/§12의 행 추가/수정 — Frozen 약속 보존.

## 8. 본 단계의 마무리 진술

> **"본 단계는 외부 학습 자료(슬라이드)에서 들어온 *Dual-Track UI + Logic TDD with MLOps* 프레임을, 본 PRD의 *Frozen 약속을 깨지 않으면서* 정직하게 수용·재해석·박제한 단계다.**
> **MLOps는 형식만 빌리지 않고 명시적 배제했고, UI는 화면이 아니라 입출력 경계로 좁혀 받았으며, *외부 강제력* 차원은 §13으로 신설하여 슬라이드가 그리지 않은 부분을 본 PRD가 *기능적으로* 닫았다.**
> **6개 결함은 *Frozen 영역을 건드리지 않으면서* 모두 닫혔으며, 그 결과 본 PRD는 *외부 분석 통과 가능 상태*로 진입했다."**

본 단계가 닫히는 순간, 후속 단계(`09_Ops_스캐폴딩_및_초기_자동화_게이트`)는 §13의 *paper-only 상태를 작동 가능한 형태*로 환원할 책임을 갖는다.
