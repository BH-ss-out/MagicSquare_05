### 0.3 본 단계가 *해야 하는 것*

- PRD §8 Test ID 카탈로그(50건) + §12 매트릭스(14행) + §13 OG 카탈로그(14건)를 *작업 단위*(TASK-XXX-1/2/3)로 *손실 없이* 환원한다.
- README와 TODO의 *책임 경계*를 결정한다 — 한쪽이 다른 쪽을 *재서술하지 않는다* (단일 진실 출처 보존).
- 사용자 지정 출처 매핑(PRD 중심 / Report+pyproject+.cursorrules 보조)을 *절 단위로* 적용 + 자기 검증한다.
- 슬라이드의 시각 문법을 *손실 없이* 채택한다 — 단, 본 PRD가 슬라이드보다 풍부한 부분(추적 매트릭스, ECB 매핑)은 *보존·확장*한다.
- TODO 정본을 `docs/` 하위(사용자 지정)에 두되, *결정 박제용 스냅샷*은 본 보고서로 분리하여 OPS-3 정신을 보존한다.

### 0.4 본 단계가 *하지 않는 것*

- 첫 RED 테스트 작성 — TDD 원칙 + 본 단계는 *작업 큐 정립*이지 큐의 *실행* 자체가 아님.
- TASK-001 ~ 003 (Pre-RED 게이트) 실제 실행 — 후속 보고서 `Report/11_Pre_RED_Closure_Log`로 이관.
- PRD/Report Frozen 영역 변경 — `Report/08` D-1, `Report/09` OD-1 정신 보존.
- `pyproject.toml` 임계값 변경 — OPS-2 (강화도 별도 PR, 본 단계는 *문서 신설*만).
- `Report/01` ~ `Report/07`의 행 변경 — 본 단계는 *진입점 + 작업 보드*만 신설.

## 1. 작업 진행 단계 (Cycle-by-Cycle)

본 단계는 *5개 사이클*로 진행되었다. 각 사이클의 입력·결정·산출을 분리해 기록한다.

### CYCLE 1 — 참조 문서 카탈로그 합의

| 항목 | 내용 |
|---|---|
| 입력 | *"To-Do 리스트를 작성하고 싶다. 무슨 문서를 참조할까?"* |
| 결정 | 4단 우선순위 외부화: ① 즉시·구체 출처 = `Report/09` §6·§7 + `Report/08` §6·§7 / ② 정확성 검증 = PRD §8/§12/§13 + 부록 A / ③ 규약·도구 보호선 = `.cursorrules` + `pyproject.toml` + `ci.yml` / ④ 맥락 인용 = `Report/01`~`Report/07`. *재서술 금지*, *링크만* 원칙. |
| 산출 | 우선순위 표 (응답 본문) — 본 보고서 §3.1에 *결정 항목*으로 박제. |
| 영향 | 본 단계 작업의 *지반*을 외부 어휘로 만들어, 후속 변경의 *합의 근거*를 확보. |

### CYCLE 2 — To-Do 구조 1차 산출 (방법론 적용)

| 항목 | 내용 |
|---|---|
| 입력 | *"[방법론을 적용하여] To-Do 구조를 작성하라. Concept-to-Code Traceability / Dual-Track / ECB / RGR / 시나리오 레벨 L0~L3 / 식별자 Epic-001·US-001·TASK-001"* + 8개 최소 작업 항목 |
| 결정 | (a) Phase별 Task 목록(0~7) + 각 Task에 8개 메타(ID/Phase/제목/Scenario/Test/Code/ECB/체크포인트) 부여. (b) PRD §8 Test ID 50건을 TASK-010 ~ TASK-091에 *모두 매핑*. (c) Pre-RED Phase 0 신설(부록 A 박제 + R-2 종결 + 환경 박제) — 첫 RED 직전 *결정적 진입 지반* 확보. |
| 산출 | Phase 0~7 + 30+ TASK + Coverage 체크포인트 7개 + ECB 위반 회귀 차단 표 (응답 본문) |
| 영향 | PRD가 *명세*에서 *작업 큐*로 환원됨 — 단, 시각적으로 슬라이드와 어휘 충돌(ECB / Phase별 묶음)이 잠재. |

### CYCLE 3 — 슬라이드 시각 문법 채택

| 항목 | 내용 |
|---|---|
| 입력 | 슬라이드 1장 ("1.3 체크박스·단계별 번호·Requirements 추적 체계", 8교시) + *"이런 형태를 참조 부탁해"* |
| 결정 | (a) Phase 단위 묶음 → **US 단위 묶음**으로 재정렬 (US-000 Pre-RED + US-001~007 기능 + US-008~009 통합 + US-010 Ops). (b) RED/GREEN/REFACTOR를 **`TASK-XXX-1/2/3` sub-task**로 수직 분해. (c) 설계 대안은 **`* 선택:`**, 검증 조건은 **`> [Checkpoint]`**로 표기. (d) 추적 매트릭스 표를 **상태 토큰**(✅/🔴/🟦/⏸/🚧) 동반으로 박제. |
| 산출 | US-000~010 + 39행 추적 매트릭스 + 진입 큐 5건 (응답 본문) |
| 영향 | 시각 문법은 *슬라이드와 1:1 일치*하면서, 본 PRD가 슬라이드보다 풍부한 부분(ECB 명시 / Req ID 다중 / Status 5종)은 *보존·확장*됨. |

### CYCLE 4 — README 출처 매핑 합의

| 항목 | 내용 |
|---|---|
| 입력 | *"README.md를 만들고 싶다. 무슨 문서를 참조할까?"* |
| 결정 | 4단 우선순위 외부화 + **기존 README(135줄)를 *갱신*하지 *교체하지 않는다*** + To-Do 본문은 README에 *전부 담지 않고* 정본 링크만 둔다 (3개 옵션 A/B/C 중 *진입점+라이브 보드 분리* 권장). |
| 산출 | 우선순위 + 권장 산출 구조 (응답 본문) |
| 영향 | README ↔ TODO ↔ PRD ↔ Report 4층 분리가 *합의됨*. 다음 사이클에서 *그대로 박제*. |

### CYCLE 5 — `docs/TODO.md` + `README.md` 박제 + 무결성 검증

| 항목 | 내용 |
|---|---|
| 입력 | *"먼저 TODO.md는 docs/ 하위에. README 본문·To-Do·검증 기준은 docs/PRD.md를 중심에 두고, 스토리·오류·계약·실행·ECB·TDD는 Report/ + pyproject.toml + Cursor 규칙, 문서 관계 한 줄은 Report/를 참조해서..."* |
| 결정 | (a) `docs/TODO.md` *신설* (404줄). (b) `README.md` *갱신* (135 → 347줄, §0 문서 관계 + §7 작업 보드 + §11 인덱스 신설 + 기존 절 보존·확장). (c) 본 보고서(`Report/10`)를 *결정 박제용 스냅샷*으로 분리하여 OPS-3 정신 보존. |
| 산출 | 2개 파일 + 본 보고서 |
| 영향 | 본 단계의 산출이 *외부 분석 가능*한 형태로 박제. 다음 커밋(TASK-001)부터는 *Pre-RED 진입 큐* 위에서만 진행됨이 결정적. |
